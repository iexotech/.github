# Contributing to IEXO repositories

1. Read the repo's README and the IEXO handbook's engineering standards. Ask for access if you don't have it.
2. Branch from `main`: `feat/…`, `fix/…` or `chore/…`. Keep branches short-lived.
3. Commit messages are imperative and describe the change. No tool branding or co-author trailers unless agreed.
4. Open a pull request using the template. Lint, type-check, tests and the secret scan must pass, where the repo has them.
5. Never commit secrets, real personal data, contracts or partner-confidential material. Use `.env.example` for configuration names.
6. Contributions are accepted only from people with a signed contributor or engagement agreement.
